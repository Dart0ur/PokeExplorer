# PokeExplorer

Android-приложение для просмотра покемонов из [PokeAPI](https://pokeapi.co/): поиск, избранное, команды, история просмотров и несколько профилей на одном устройстве. Данные кэшируются локально, поэтому сохранённое работает без сети.

---

## Возможности

| Экран | Что умеет |
|---|---|
| **Список** | Первые 30 покемонов, поиск по имени с задержкой 400 мс, фильтр «Все / Избранное», pull-to-refresh, сердечко, кнопка «Скрыть» |
| **Детали** | Характеристики, типы, статы, описание из `pokemon-species`. Кнопка «В команду». Открытие записывается в историю |
| **Избранное** | Отмеченные покемоны текущего профиля. Работает без сети |
| **Команды** | Создание, переименование и удаление (с подтверждением). Счётчик «3/6» |
| **Команда** | Участники по позициям 1–6, заметка к каждому, удаление с пересчётом позиций |
| **История** | 20 последних просмотров, удаление одной записи, «Очистить всё» |
| **Профили** | Несколько профилей. У каждого свои избранное, команды, история, скрытые и настройки |
| **Настройки** | Срок жизни кэша (TTL), «Показывать скрытых» |

### Бизнес-правила

- В команде **не больше 6 покемонов**. Один покемон не может попасть в одну команду дважды, но может быть в разных командах.
- Проверка лимита и вставка выполняются под `Mutex`, поэтому двойное нажатие не даст 7 участников.
- После удаления участника позиции пересчитываются без пропусков (1, 2, 3…).
- Повторное открытие покемона не создаёт новую запись в истории, а поднимает старую наверх.
- Скрытие работает как фильтр поверх загруженных данных и не делает повторный запрос в сеть.
- Фильтр «Избранное» читает данные из Room, поэтому работает офлайн и сразу реагирует на снятие сердечка.

## Архитектура

```
UI (Compose)  ──Event──▶  ViewModel  ──▶  Repository  ──▶  Room DAO / PokeAPI / DataStore
      ▲                      │
      └──── StateFlow<UiState> ┘
```

- **Экран не знает, откуда берутся данные.** Он получает `uiState` и отправляет события через `onEvent(...)`.
- **ViewModel** собирает состояние из нескольких потоков через `combine`. Например, список строится из запроса, фильтра, счётчика «Обновить», избранного и скрытых.
- **Репозитории** работают с данными **активного профиля**. Профиль приходит потоком `ActiveProfileProvider.activeProfileId`, и при его смене `flatMapLatest` сам переключает все данные.
- **Один источник профиля.** `DataStoreActiveProfileProvider` и `UserPreferencesRepository` читают один и тот же ключ DataStore, поэтому избранное, настройки, история, скрытые и команды переключаются вместе.

### Навигация

| Маршрут | Экран |
|---|---|
| `list` | Список (стартовый) |
| `detail/{id}?name=` | Детали |
| `favourites` | Избранное |
| `profiles` | Профили |
| `settings` | Настройки |
| `history` | История |
| `teams` | Список команд |
| `team/{teamId}` | Одна команда |

На экране деталей работают ещё две ViewModel, которые берут id и имя покемона из аргументов маршрута:
- `HistoryRecorderViewModel` записывает просмотр один раз за открытие экрана, повороты экрана не создают лишних записей;
- `AddToTeamViewModel` с `AddToTeamOverlay` даёт кнопку «В команду» поверх экрана, не меняя `PokemonDetailScreen`.

## База данных

Room, файл `pokeexplorer.db`, **версия 3** (миграции `MIGRATION_1_2`, `MIGRATION_2_3`). При первом создании `DefaultProfileCallback` добавляет профиль по умолчанию.

| Таблица | Назначение | Ключ |
|---|---|---|
| `profiles` | Профили пользователей | `id` |
| `favourites` | Избранное | `profileId` + `id` |
| `teams` | Команды | `id`, FK → `profiles` (CASCADE) |
| `team_members` | Состав команд: связь многие-ко-многим | `teamId` + `pokemonId`, FK → `teams` (CASCADE) |
| `history` | История просмотров (не больше 20 на профиль) | `profileId` + `pokemonId` |
| `hidden_pokemon` | Скрытые покемоны | `profileId` + `pokemonId` |
| кэш покемонов / индекс | Кэш ответов PokeAPI с TTL | `TODO` |
| синхронизация | Служебные данные WorkManager (`SyncDao`) | `TODO` |

### Связь «команда ↔ покемон»

`team_members` — это таблица связи с собственными полями:
- `position` — место в команде (1–6);
- `note` — заметка («танк», «ловец»), её можно редактировать на экране команды;
- `addedAt` — время добавления.

Имя и картинка покемона хранятся прямо в строке связи. Поэтому экран команды открывается без запроса в сеть и без JOIN.

Число участников для списка команд считает один запрос `observeMemberCounts` (`GROUP BY teamId`), а не отдельный запрос на каждую команду.

## Кэш и синхронизация

- **TTL.** Срок жизни кэша задаётся в настройках. Пока данные свежие, они берутся из Room, а устаревшие загружаются из сети заново.

## Тесты

Юнит-тесты лежат в `app/src/test` и запускаются на компьютере, эмулятор не нужен.

```bash
./gradlew testDebugUnitTest
```

Сейчас **73 теста, все зелёные**. Основные наборы:

| Файл | Что проверяет |
|---|---|
| `TeamRepositoryTest` (11) | Лимит 6, `AlreadyInTeam` важнее `TeamFull`, позиции и их пересчёт, счётчик участников, разделение по профилям, обрезка пробелов |
| `PokemonListViewModelFlowTest` (10) | Порядок состояний через Turbine: `Loading → Success`, `Error → Retry → Success`, debounce поиска, `Empty`, фильтр «Избранное», «Обновить», скрытие без повторного запроса, «Показывать скрытых» |
| `PokemonDataTest` (15) | Маппинг PokeAPI (id из url, типы по slot, выбор английского описания), избранное, разделение избранного по профилям |

Room в тестах не используется. Вместо DAO подставляются реализации в памяти (`FakeTeamDao`, `FakeFavouriteDao`), вместо профиля — `FakeActiveProfileProvider`, который тест может переключать.

**Баг, найденный тестами.** Фильтр «Избранное» раньше брал покемонов из общего индекса. Если покемона не было в индексе или не было сети, он пропадал из избранного. Теперь данные читаются из Room.
